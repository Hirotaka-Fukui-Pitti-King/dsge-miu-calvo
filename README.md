# Динамическое общее равновесие с капиталом, деньгами и негибкими ценами

**Назначение проекта.** Сравнить динамические реакции одной и той же экономики на технологические и денежно-кредитные шоки при гибких ценах и при установлении цен по правилу Кальво. Монополистическая конкуренция, предпочтения, технология, капитал и правило центрального банка одинаковы в обоих режимах: изменяется только возможность пересмотра цен.

**Краткое описание для GitHub:** «Модель динамического общего равновесия с капиталом, деньгами в функции полезности и ценообразованием Кальво: уравнения, стационарное состояние, проверка определённости и импульсные отклики».

## Состояние исследования

В ходе первого этапа реализованы независимые Jacobian исходных условий, QZ-проверка, таблицы стационарных остатков и сравнение независимых IRF. Все 19 локальных тестов успешно выполнены. Детальный отчёт: `docs/03_verification.md`. Проверка полной нелинейной стохастической модели не выполнялась.

Реализованы аналитическое стационарное состояние, линеаризация первого порядка, редуцированные матрицы динамики, проверка условий Бланшара — Кана, а также импульсные отклики для двух режимов цен. Автоматические проверки и локальный запуск выполнены. Численные результаты относятся к **иллюстративной калибровке**, а не к оценённой структурной модели. Первоначальный GitHub Actions для исходной версии успешно завершился; новый коммит этапа 1 требует отдельной проверки.

## Теоретическая структура

- Репрезентативное домохозяйство выбирает потребление, труд, капитал, номинальные облигации и деньги, непосредственно обеспечивающие услуги ликвидности.
- Промежуточные фирмы производят дифференцированные товары с использованием труда и капитала; между фирмами факторы производства полностью мобильны.
- Гибкие цены: оптимальная надбавка к предельным издержкам постоянна.
- Цены по Кальво: вероятность пересмотра цены за период равна `1 − θ`; в нелинейной версии необходимы рекурсии оптимальной цены и ценовая дисперсия.
- Центральный банк устанавливает номинальную ставку по правилу реакции на инфляцию и отклонение выпуска от стационарного уровня.
- Денежные остатки определяются из спроса на ликвидность. При используемой аддитивной сепарабельности деньги не воздействуют на реальные решения напрямую.

Важно: это **гибкоценовая монополистически конкурентная экономика**, а не отдельная модель совершенной конкуренции. Такое сравнение изолирует эффект негибкости цен.

## Как воспроизвести

Необходимы установленный Python и доступ к пакетам из `requirements.txt`. Запускать из корня проекта:

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m src.audit
python -m src.experiment
```

Программа сохраняет два набора CSV-файлов (для каждого режима и каждого шока) и отдельный SVG-файл для каждой переменной и каждого шока. Изменение параметров выполняется через класс `Parameters` в `src/model.py`.

## Базовая калибровка

| Параметр | Значение |
|---|---:|
| Коэффициент дисконтирования `β` | 0,99 |
| Доля капитала `α` | 0,33 |
| Амортизация `δ` | 0,025 |
| Эластичность замещения товаров `ε` | 6 |
| Вероятность сохранения цены `θ` | 0,75 |
| Обратная межвременная эластичность `σ` | 1 |
| Кривизна издержек труда `φ` | 1 |
| Реакция ставки на инфляцию `φπ` | 1,5 |
| Реакция ставки на выпуск `φy` | 0,125 |
| Персистентность технологии `ρa` | 0,9 |
| Персистентность денежного шока `ρv` | 0,8 |

Эти значения служат исключительно для демонстрации. В частности, шок технологии равен `0,01` логарифмической единицы, а инновация денежного правила — `0,0025` единицы логарифма валовой ставки.

## Границы результатов

Текущая версия решает только **линеаризованную модель первого порядка**. Ценовая дисперсия, благосостояние второго порядка, премии за риск, капитал, специфичный для фирмы, и издержки корректировки инвестиций здесь не рассчитываются. В полном нелинейном равновесии также нужно явно согласовать государственный бюджет, выпуск номинальных обязательств и номинальный уровень цен.

Все содержательные описания, комментарии, сообщения программы и документация ведутся на русском языке. Латинские технические имена файлов, параметров и программных интерфейсов сохраняются для совместимости с инструментами разработки.
